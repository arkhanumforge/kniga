# Поиск по книге (локально, прежний прототип)

**Внимание:** этот поиск не является выборкой канона или знаний героя. Он не адаптирован к ревизии документации. До проверки нового маршрута на этапе 7 обращаться к исходным Markdown в нужной версии и читать все четыре карты знаний полностью. См. [архитектуру RAG](<../Архитектура RAG.md>) и [статический аудит](<../Карта междокументной сверки.md#2-фактический-охват-старого-генератора>).

Прежний прототип работает локально без ключей и интернета (нужен Python и локальная копия репозитория). Команды сохранены для диагностики; обновление старого индекса после закрытия сцены или главы само по себе не гарантирует корректную выборку.

**Обновить индекс:**

```text
python rag/build_index.py
```

**Спросить:**

```text
python rag/query.py "что Лиза знает про кривого"
```

Фактически включаются Мир, Персонажи, События, Хронология, Шпаргалка, Стиль, Сейчас, GENERAL, Глава*, План главы*, Хвост главы*. Это смешанный набор, а не канон: туда попадают 8.1/8.3 и будущие планы без фильтра версии, момента и POV.
После выделения первой главы старый скрипт включает Глава 1.md по префиксу «Глава »; сборный файл удалён из рабочей ветки. Не индексируются План лора.md, четыре карты знаний, справочник стиля, химия и отношения, арки. Результат — до пяти лексических совпадений, сниппеты до 500 символов; нужно дочитывать первоисточник. Нет проверки свежести по SHA и гарантии доступа через GitHub-коннектор с телефона. Логика скриптов пока не менялась; индекс после миграции необходимо перестроить, полноценная адаптация и проверка — этап 7.


## 7а: пилот навигации (не выборка канона)

[Манифест](navigation/manifest.json), [реестр](source_registry.json), [генератор](build_navigation.mjs), [отчёт и ограничения](phase-7a.md). В docs-revision сверить source_commit и входные blob SHA с текущим деревом; открыть pointer для нужной карты и оригинал по commit/диапазону. Для прочих документов пока прямое чтение. При несовпадении или неполноте — прямой fallback. Указатели только для автора, могут содержать спойлеры. Все четыре карты читать полностью.

В checkout с Node.js и Git, только docs-revision:
```sh
node rag/build_navigation.mjs --write
node rag/build_navigation.mjs --check
```
Скрипт читает закоммиченный HEAD, не незакоммиченные правки; source_commit может быть предком коммита указателей, свежесть по blob. Не пушит и не меняет канон. CLI и автоматический workflow пока не испытаны. Старый Python-поиск остаётся прежним прототипом. Следующий 7б.


## 7б: полный авторский указатель и очередь проверки

Манифест теперь содержит pointer для каждого из 40 зарегистрированных источников; у четырёх карт есть отдельные K/P-ID, holder, статус, learned_at (дословное поле), диапазон. Планы отделены. `chapter_hint` — номер в ID, не точная временная граница; один ID может содержать несколько моментов. Указатель и очередь кандидатов не являются срезом доступных герою фактов. Четыре карты читать полностью; не считать отсутствие ID в очереди доказательством отсутствия знания. Для альтернатив, новой главы после 8 и неизвестной точки — только прямой маршрут, пока формат не обновлён.

В среде с Git/Node после проверки свежести:
```sh
node rag/search_navigation.mjs author "пленника сон"
node rag/search_navigation.mjs review liz 8 inside
```
Author — поисковое дополнение по словам, приблизительным словоформам и четырём группам алиасов. Top-20 окон по 30 строк не являются полными нормами; открыть родительский раздел, условия, исключения и источники. Review — очередь ручной проверки отдельного субъекта, без текста, тем и планов; даже при end проверять поздние части, передачу и степень уверенности. `selection_ready=false`. Лексический CLI и оболочка Git/Node пока не проверены на реальном checkout; чистое JS-ядро проверено (100 тестов, в том числе 96 комбинаций границ). До проверки сохранён режим прямого чтения. Старый Python-поиск не использовать как проверку канона.
