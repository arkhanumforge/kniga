## С телефона через GitHub, без локального скрипта

1. Работать в main и закрепить SHA её головы. Установить принятую версию, главу, сцену и POV.
2. Открыть GENERAL и маршрут задачи. Для полной подготовки — все четыре карты, Мир по механикам, полные нужные портреты, ранний опыт, физика, Стиль и Химия/отношения по сцене.
3. Открыть `rag/navigation/manifest.json` по выбранному ref, сверить состав и blob SHA входов с текущим полным деревом. Проверить, что нужные pointer существуют. `source_commit` может быть предком коммита указателей; свежесть определяется входными blob, а не равенством двух SHA.
4. В pointer (например `navigation/knowledge-liz.json`) искать заголовок, ID, learned_at и диапазон. Указатели AUTHOR-ONLY; даже заголовки и темы могут содержать спойлеры. Открывать исходный файл по закреплённому commit и диапазону, целый нужный раздел с условиями, исключениями и первичными ссылками. Для поиска раннего опыта использовать также главы, События, Хронологию, профильные документы. Не считать отсутствие результата отсутствием факта.
5. Если указатель устарел, файл не зарегистрирован, ответ обрезан или поиск недоступен — прямой маршрут, с диапазонами и контролем полноты. Не скрывать блокер. Карты и планы не подменяют первичную сцену; чужое знание и author/planned не попадают в реплики или мысль героя.

В реестре 43 источника и 15 исключений после добавления трёх команд; пофайловые указатели разбиты по источникам. В четырёх картах 175 ID (162 K, 13 P). `chapter_hint` не точная временная граница: K-запись может включать позднее уточнение, неизвестный момент и авторскую оговорку. Не читать очередь ID как готовый срез знаний.

## В среде с Git/Node.js

Только на checkout main. Генератор читает закоммиченный HEAD, не рабочие незакоммиченные правки. Никаких внешних API, ключей и зависимостей:

```sh
node rag/build_navigation.mjs --check
node rag/build_navigation.mjs --write
node rag/search_navigation.mjs author "пленника сон"
node rag/search_navigation.mjs author K-LIZ-008-06
node rag/search_navigation.mjs review liz 8 inside
node rag/test_navigation.mjs
node rag/test_corpus.mjs
```

Author — лексические кандидаты (точные слова, приближённые словоформы, алиасы, заголовки), top-20 окон; открыть полный родительский раздел (`section_start`–`section_end`) и связанные условия. Точное K/P-ID возвращает одну адресную запись, в том числе плановую с её статусом; не подтверждает доступность герою. Review — очередь ручной проверки отдельного holder для начала/середины/конца принятых глав 1–8; только ID/диапазоны, без текста, тем и планов. Не годится как доказательство полноты. Альтернативы, неопределённые точки и главы после 8 — прямой маршрут до обновления формата и проверки новой линии. Полный семантический поиск/лемматизатор и компактный доказанный POV-срез не внедрены.

## Автоматическое обновление

[Workflow](../.github/workflows/rag-navigation.yml) действует на push в main и ручной запуск. Стандартный бесплатный runner публичного репозитория; никаких новых секретов/сервисов. Сначала синтетические CLI-тесты, затем проверка актуальности, при необходимости пересборка, контроль корпуса, коммит только rag/navigation и fast-forward push. Конкурентное изменение — пересборка из новой головы, до трёх попыток. Изменение одних производных указателей не запускает цикл. Прямой fallback при сбое/отсутствии результата.

Исторически на docs-revision проверены три успешных запуска [46038927873](https://github.com/arkhanumforge/kniga/actions/runs/46038927873), [46039259996](https://github.com/arkhanumforge/kniga/actions/runs/46039259996), [46039512738](https://github.com/arkhanumforge/kniga/actions/runs/46039512738); второй автоматически опубликовал обновление `b7473ee0cf790c9d6bbb8d247676c91ea1985e67` после 7г. Синтетический тест проверяет изменение, удаление, неизвестный источник, свежесть, локальный поиск; реальный корпус — 175 ID, 430 вхождений, 96 очередей, 5 точных поисков, 7/7 заранее выбранных целей лексического пилота в top-20 (все в top-6). Это не полноценная оценка recall/precision и не художественный эксперимент.

При принятии новой главы/смене версии агент синхронизирует содержательные карты и классификацию `source_registry.json` (добавить принятую главу в mainline-source, альтернативу отдельно, исключения явно). При удалении источника обновить реестр по разрешённой версии. Не перекладывать техническую работу на автора. Генератор намеренно отвергает неизвестные или исчезнувшие зарегистрированные файлы, чтобы не принять альтернативу автоматически. Индекс не определяет статус принятия и не меняет канон. Пока новые границы не проверены, полный ручной маршрут остаётся.

## Исторический прототип

`build_index.py` и `query.py` сохранены для истории/диагностики, не используются действующими правилами. Прежний Python-поиск смешивал главы, альтернативы и планы, пропускал карты знаний/химию/отношения, ранжировал словоформы без фильтра версии/POV, обрезал текст и не проверял SHA. Не строить его как источник канона. История пилота: [7а](phase-7a.md), [7г](phase-7g.md), журнал ревизии и прежняя версия README в истории Git.
